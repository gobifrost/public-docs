---
title: How to Provision Users with SCIM
description: Connect an organization’s directory and map its groups to Bifrost roles.
---

Use a SCIM connection to provision users and apply group-based access in one Bifrost organization. Set up [SSO](/docs/how-to-guides/authentication/sso/) separately for sign-in.

1. In **Users → Identity Providers**, select **Add Provider**. Choose the organization and directory provider, set a token lifetime, and select **Create Connection**.
2. Copy the **Tenant URL** and the SCIM token shown after creation. Enter them in your directory’s SCIM provisioning settings. Store the token securely because Bifrost shows its value once.
3. Assign a pilot user and group to your directory’s provisioning app. Start provisioning, then check that the group appears on the connection in Bifrost.
4. Edit the group’s mapping and select the Bifrost roles its members should receive. Choose **Access Only** if the group should grant access without a role.
5. Verify the pilot user appears in **Users** with the expected access. Remove the user from the mapped group in the directory and verify that the group’s grants are revoked after the directory sends the update.

Once the connection has a group mapping, provisioned users need membership in at least one mapped group to retain access. Bifrost applies grants on its two-minute access pass. Privileged roles must be assigned directly in Bifrost.

### SCIM reference

The **Tenant URL** is the base for SCIM 2.0 requests. Send the connection token in the `Authorization: Bearer` header and use `application/scim+json` for request bodies.

| Relative path | Methods |
| --- | --- |
| `/ServiceProviderConfig`, `/ResourceTypes`, `/Schemas` | GET |
| `/Users`, `/Groups` | GET, POST |
| `/Users/{id}`, `/Groups/{id}` | GET, PUT, PATCH, DELETE |

Rotate an expiring token from the connection’s provisioning section and update the directory’s credentials. The previous token stops working when you rotate it.
