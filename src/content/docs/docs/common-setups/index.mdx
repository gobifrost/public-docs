Common Setups are end-to-end runbooks for systems that span Bifrost, a provider account, and customer environments. Each setup begins with read-only discovery so you can reuse what is healthy, repair what is incomplete, and create only what is missing.

## How Common Setups Work

1. Choose the capabilities you want, not a copied permission list.
2. Authorize a read-only inventory of the provider, Bifrost, and a development customer.
3. Review a `reuse`, `repair`, or `create` recommendation for every component.
4. Approve writes in small phases, with a verification check after each phase.
5. Complete the few human-only steps such as MFA, tenant-wide consent, and customer approval.
6. Keep the resulting IDs, mappings, grants, and acceptance results as the operating record.

The runbooks prefer supported APIs and Bifrost workflows over portal screenshots. Microsoft portals remain necessary where Microsoft does not expose an equivalent application-only API.
